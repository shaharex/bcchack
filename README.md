# AI Requirements Validator

Проверяет требования в Markdown и PDF с помощью Gemini, сверяет цитаты с источником и формирует отчёт на русском языке.

## Установка и ключ Gemini

Откройте PowerShell в корне проекта. Используйте Python 3.11 или новее.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
Copy-Item .env.example .env
```

Создайте ключ в Google AI Studio и запишите его в поле `GEMINI_API_KEY` файла `.env`. CLI читает `.env` из текущего каталога. Переменные процесса имеют приоритет. `GEMINI_MODEL` задаёт модель, `GEMINI_TIMEOUT_MS` — таймаут HTTP-запроса в миллисекундах, `GEMINI_MAX_ATTEMPTS` — число попыток. Укажите конкретный ID модели и `VALIDATOR_AGENT_VERSION` с хешем коммита или тегом, если нужен воспроизводимый паспорт прогона. [Ключи Gemini API](https://ai.google.dev/gemini-api/docs/api-key)

## Запуск

```powershell
python -m requirements_validator --input path/to/requirements.md --output report.md
python -m requirements_validator --input path/to/requirements.pdf --output report.md
```

Передайте документ организаторов через `--input`. Каталог для отчёта должен существовать. CLI записывает UTF-8 Markdown после завершения анализа. При ошибке команда возвращает ненулевой код и выводит сообщение в stderr.

Отчёт содержит паспорт прогона, карту требований, оценку каждого требования, проверку спецификации, подтверждённые дефекты с цитатами и серьёзностью, вопросы к заказчику, сводку и рекомендации по готовности. Карта указывает отдельно место исходного идентификатора и место формулировки. Идентификаторы `L3-L5` обозначают диапазоны строк Markdown, `P2` — вторую страницу PDF. Смещения в квадратных скобках отсчитываются от начала блока в символах Unicode, начиная с нуля. Правая граница исключается.

Извлечённые элементы получают номера `R-001`, `R-002` в порядке исходных позиций. Для каждого блока сохраняется его роль в проверке. Контракты и факты спецификации, критерии приёмки, составные и атомарные требования различаются в карте. Пропуск блока или строки в анализируемой таблице вызывает повторную проверку извлечения. Отчёт показывает цитаты и исходы подтверждённых конфликтов, а также основания для отклонения кандидатов.

Серьёзность зависит от подтверждённого последствия. Высокая означает, что нельзя надёжно реализовать или проверить существенное поведение. Средняя указывает на необходимое решение ограниченного масштаба. Низкая относится к локальным замечаниям документации. Python присваивает уровень после проверки доказательств. Для настройки задайте `VALIDATOR_SEVERITY_OVERRIDES='{"verifiability":"high"}'` в `.env`. В Python можно переопределить обоснование через `SeverityRule`.

## Ограничения

- Markdown должен быть в UTF-8. PDF должен содержать доступный текстовый слой. При пропуске страницы с изображениями без текстового слоя CLI выводит предупреждение с номером страницы. Выполните OCR перед проверкой отсканированных страниц. Порядок текста в многоколоночных PDF и таблицах зависит от извлечения PyMuPDF. Раздел PDF определяется закладками на уровне страниц.
- Документ и данные анализа передаются в Gemini. Длинные документы ограничены контекстом, объёмом ответа и квотами модели. Для каждого извлечённого требования выполняется отдельный запрос на проверку.
- Цитаты сверяются посимвольно с текстом парсера. Полнота извлечения, смысловая связь доказательств и качество вопросов зависят от модели и требуют экспертной проверки.
